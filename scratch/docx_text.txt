1. บทนำและวัตถุประสงค์
เอกสารฉบับนี้จัดทำขึ้นจากการเข้าศึกษาระบบ PMT (Project Management Tool) ที่ให้บริการอยู่จริงบน https://buildflowx.online โดยสำรวจทุกเมนูหลักที่เข้าถึงได้ (16 เมนู) เพื่อสรุปแบบ Functional Design ของระบบในสภาพปัจจุบัน สำหรับใช้เป็นฐานในการวางแผนพัฒนาต่อยอดให้ระบบสมบูรณ์ยิ่งขึ้น ทั้งในมิติของฟังก์ชันการทำงาน ความสอดคล้องของข้อมูล และประสบการณ์ผู้ใช้งาน
ขอบเขตการศึกษาอยู่ที่การสังเกตพฤติกรรมระบบผ่านหน้าจอ (UI-level Black-box Exploration) โดยไม่มีสิทธิ์เข้าถึงซอร์สโค้ดหรือฐานข้อมูลเบื้องหลัง ข้อมูลบางส่วนที่แสดงในระบบ ณ ขณะสำรวจเป็นข้อมูลตัวอย่าง/อยู่ระหว่างทดสอบ (เช่น โครงการเพียง 2 รายการ พนักงาน 5 คน) จึงอาจไม่สะท้อนสเกลการใช้งานจริงทั้งหมด
2. ภาพรวมระบบ (System Overview)
PMT เป็นระบบบริหารจัดการโครงการสำหรับธุรกิจงานติดตั้ง งานก่อสร้าง งานรีโนเวท งานบิวท์อิน และงานซ่อมบำรุง (Maintenance) ครอบคลุมตั้งแต่การหาลูกค้า (Lead Generation) จนถึงการส่งมอบงานและปิดโครงการ โดยผนวกแนวคิดการบริหารงานแบบ Agile/Kanban (Sprint, Backlog, Board) เข้ากับกระบวนการงานภาคสนาม (Site Survey, QC, Check-in/out) และระบบบริหารต้นทุนแรงงาน (Timesheet-based Costing) เข้าไว้ด้วยกัน ชื่อระบบต้นแบบที่ปรากฏในเอกสารช่วยเหลือภายในคือ NexTime ซึ่งสะท้อนว่าฐานระบบถูกพัฒนาเป็นแพลตฟอร์มบริหารโครงการทั่วไป แล้วนำมาปรับให้เข้ากับธุรกิจติดตั้ง/รีโนเวทในนาม PMT
กระบวนการหลักของระบบ (End-to-End Flow) มีลำดับดังนี้:
Lead (ลูกค้ามุ่งหวัง) — บันทึกข้อมูลผู้สนใจ พร้อมพิกัดและช่องทางติดต่อ
แปลงเป็นโครงการ (Convert to Project) — สร้างรหัสโครงการ (เช่น P050826-001) และเอกสารอ้างอิง (Survey Ticket, QT Number)
ขั้นตอน Workflow ของโครงการ — ซื้อสำรวจ -> QC (สำรวจหน้างาน) -> ออกแบบ & ใบเสนอราคา -> ลูกค้ายืนยัน/ชำระเงิน -> ส่งมอบงาน
แผนงานและ Task — สร้าง Milestone/Gantt อัตโนมัติจากแม่แบบ (Master Template) แตกเป็น Task/Subtask บริหารผ่าน Kanban Board และ Sprint
ปฏิบัติงานหน้างาน — ช่างเช็คอิน/เช็คเอาท์พร้อมรูปถ่าย และบันทึก Timesheet
ต้นทุนและรายงาน — ระบบคำนวณต้นทุนจากชั่วโมงที่บันทึกจริง (Actual Hours) เทียบ Labor Rate ต่อ Role แสดงในรายงาน HR & Cost
3. บทบาทผู้ใช้งานและสิทธิ์การเข้าถึง (Roles & Permissions)
ระบบแบ่งสิทธิ์เป็น 2 ระดับตามที่ระบุใน FAQ ของระบบ คือ User ในระบบ (Global Role) และ User ใน Project ซึ่งเป็นคนละแนวคิดกัน:
Global Role: Admin, Manager, Employee, User — กำหนดสิทธิ์การเข้าถึงเมนูระดับระบบ (เช่น การจัดการผู้ใช้งาน, ตั้งค่าระบบ)
Project Role / Permission Scheme: กำหนดสิทธิ์เฉพาะภายในแต่ละโครงการ เช่น edit task, assign task, create task, delete task, browse project, manage members, manage sprints, manage releases, transition task
ผู้ใช้งานตัวอย่างในระบบ: isarachootip (Admin/Management), Tawatchai Nimpradi (Manager/Operation, ทักษะ UI/UX), John Doe (Manager/Engineering), Jane Smith และ Mike Johnson (Employee)
หน้า ช่างติดตั้ง & ทีมงาน (/team) ยังทำหน้าที่เป็นศูนย์กลางอนุมัติ Timesheet (Pending Approvals) และตารางการทำงานที่บ้าน (WFH Schedule) ซึ่งบ่งชี้ว่าระบบถูกออกแบบให้รองรับทั้งพนักงานสำนักงาน (Manager/Employee) และช่างภาคสนามในโครงสร้างสิทธิ์เดียวกัน

5.2 Master Task Templates และ Workflow Stages
แต่ละประเภทโครงการมี Full Workflow Stages มาตรฐานร่วมกัน 5 ขั้นตอน ได้แก่ (1) ซื้อสำรวจ (Survey Request) (2) QC (สำรวจหน้างาน) (3) ออกแบบ & ใบเสนอราคา (4) ลูกค้ายืนยัน/ชำระเงิน (5) ส่งมอบงานเสร็จสมบูรณ์ ยกเว้น Quick Service ที่มี Task Template เฉพาะ 3 ขั้นย่อย (สำรวจและประเมินงานหน้างาน -> ดำเนินการแก้ไข/ซ่อมแซม -> ตรวจสอบและส่งมอบงาน) สอดคล้องกับลักษณะงานเร่งด่วนที่ไม่ต้องผ่านขั้นตอนออกแบบเต็มรูปแบบ
ในหน้าตั้งค่าระบบ (Settings -> Milestone Templates) ยังมีชุดแม่แบบเพิ่มเติมอีก 41 รายการ แบ่งกลุ่มเป็น General, สร้างครัว, Kitchen Renovation, งานรีโนเวทบ้าน, งานระบบไฟฟ้า-ประปา, Quick Service, Installation ซึ่งกำหนดสัดส่วนระยะเวลา (Start % ถึง End % ของระยะเวลาโครงการทั้งหมด) และระดับความสำคัญ (Priority) ของแต่ละงานย่อยไว้ล่วงหน้า เพื่อให้ระบบสร้างแผนงาน/Gantt อัตโนมัติเมื่อเปิดโครงการใหม่
5.3 อัตราค่าแรง (Labor Rates)
ระบบกำหนดอัตราค่าแรงมาตรฐานรายชั่วโมง/รายวันแยกตามตำแหน่งงาน (Resource Role) เช่น Business Solution Analyst, Tech Lead, Backend/Frontend Developer, QA, Scrum Master, DevOps, Application Support (อัตราตั้งต้นเท่ากันทุกตำแหน่งที่ 6,500 บาท/8 ชม. หรือ 812.50 บาท/ชม. ในข้อมูลตัวอย่าง) ใช้เป็นฐานคำนวณต้นทุนในหน้ารายงาน HR & Cost
6. จุดสังเกตและข้อเสนอแนะเพื่อพัฒนาระบบให้สมบูรณ์ (Gap Analysis & Recommendations)
จากการสำรวจพบประเด็นที่ควรพิจารณาปรับปรุงเพื่อให้ระบบมีความสมบูรณ์และสอดคล้องกับการใช้งานจริงมากขึ้น ดังนี้:
ประเด็นที่พบ (Gap)
ผลกระทบ
ข้อเสนอแนะเพื่อพัฒนาให้สมบูรณ์
ชื่อขั้นตอน Workflow ไม่ตรงกันระหว่างหน้า Dashboard (Stage Progression: Design for Purchase, Survey for Design, Design & Proposal, Submit to Sales, คุยกับลูกค้า) กับ Master Workflow Stages ในหน้า Maintain Master (ซื้อสำรวจ, QC, ออกแบบ&ใบเสนอราคา, ลูกค้ายืนยัน/ชำระเงิน, ส่งมอบงาน)
ผู้ใช้งานสับสนว่าขั้นตอน "จริง" ของโครงการคืออะไร รายงานและ KPI อาจตีความคลาดเคลื่อน
รวมแหล่งข้อมูล Workflow Stage ให้เป็นชุดเดียว (Single Source of Truth) แล้วอ้างอิงจากจุดเดียวกันทั้ง Dashboard, Project Board และ Master Data
ฟิลด์ "ผู้รับผิดชอบ" ในตารางรายชื่อโครงการแสดงเป็น "Unknown" ทั้งที่หน้ารายละเอียดโครงการมี PIC (เช่น PAKPOOM J.) อยู่แล้ว
ข้อมูลไม่ถูกต้องกระทบการติดตามงานและการมอบหมายความรับผิดชอบ
ตรวจสอบการ Join ข้อมูล PIC/ผู้รับผิดชอบจากตาราง Project ให้แสดงผลถูกต้องในทุกหน้าที่เกี่ยวข้อง
ประเภทโครงการ "test" ยังปรากฏอยู่ใน Master Data (Project Types, Task Templates, Workflow Stages) ของระบบที่ใช้งานจริง
ข้อมูลทดสอบปนกับข้อมูล Production อาจถูกเลือกใช้งานโดยไม่ตั้งใจ

7. สรุป
ระบบ PMT ในปัจจุบันมีโครงสร้างฟังก์ชันครบถ้วนตามแนวคิดการบริหารโครงการสมัยใหม่ ตั้งแต่การหาลูกค้า การวางแผนงาน การติดตามหน้างาน จนถึงการคำนวณต้นทุนและรายงานผล อย่างไรก็ตาม ระบบยังอยู่ในช่วงเริ่มต้นของการใช้งานจริง (ข้อมูลตัวอย่างจำนวนน้อย) และมีร่องรอยของการนำแพลตฟอร์มบริหารโครงการซอฟต์แวร์ทั่วไป (NexTime) มาปรับใช้ ซึ่งบางฟีเจอร์/ศัพท์เฉพาะยังไม่ถูกปรับให้เข้ากับบริบทธุรกิจติดตั้ง-รีโนเวทอย่างสมบูรณ์ การพัฒนาต่อยอดควรมุ่งเน้น 3 ด้านหลัก คือ (1) ความสอดคล้องของข้อมูลและคำศัพท์ Workflow ระหว่างหน้าจอ (2) การเพิ่มโมดูลออกเอกสารจริง (ใบเสนอราคา/BOQ/แบบแปลน) ที่เชื่อมกับโครงการโดยตรง และ (3) การทดสอบระบบกับผู้ใช้งานจริงแบบครบวงจรอย่างน้อย 1 รอบโครงการ ก่อนขยายผลใช้งานเต็มรูปแบบ
